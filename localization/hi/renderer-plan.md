# Hindi shaping repair and regression plan

This is a static proposal, not a repair or a runtime pass. Steam build 11915262 uses Ren’Py 8.0.3.22090809. `text-assets/multilingual-devanagari-probe.Z7siFr/visual-review-01.json` reports the opening dialogue displays the virama in क्ष and misplaces the vowel in क्षितिज; the input prompt also shows the unshaped cluster. `NV-0903` has missing Latin glyphs with the sampled Devanagari font. The associated `runtime-evidence.json` records font loading, accepted Devanagari input and advancement after a wait, but the input screenshot precedes insertion and settings visual review is pending. The previously reported behavior does not prove correct glyph layout, caret behavior or final Hindi rendering.

## Candidate and decision boundary

Investigate a supported complex shaping path with HarfBuzz, available upstream in Ren’Py 8.2, on a disposable copy after an explicit owner decision authorizes the engine change and runtime work. Assess compatibility with this game's scripts, save format, packaging, and existing locales before choosing an upgrade; do not modify the shared engine or game in this assignment. An alternative locale-scoped shaping adapter requires a concrete design covering logical Unicode text, clusters, input editing, line wrapping, interpolation and all text styles; neither a font swap nor pre-shaped static glyphs alone solves dynamic input. If neither route can support all surfaces, keep Hindi blocked. The font candidate is Noto Sans Devanagari 2.007, tested file SHA-256 `4e3c66638958c3e2ab5d37f47a8deb89fffeb7be9985c665a519bbc7ba762313`. Choose and license-check a Latin fallback covering `NV-0903`; ensure fallback font selection does not split Devanagari clusters. Font cmap coverage is necessary, not evidence of shaping.

## Bounded regression matrix for an authorized joint pass

1. Reproduce the original synthetic `नमस्ते, कृपया क्षितिज और दृष्टि देखिए।` with `NV-0903` in actual dialogue, nameplate, settings, input prompt and editable input. Check क्ष conjunct formation, pre-base ि placement, other conjuncts/marks and Latin glyphs against a trusted shaping reference; inspect wrapping and clipping at actual sizes. Test mixed Hindi/Latin/numbers and punctuation around interpolation and across line breaks. Preserve Unicode source and placeholders.
2. Enter `क्षितिज` and a mixed Latin/Devanagari name, observe composition, caret placement, movement, selection, backspace/delete across grapheme clusters, submission, 12-character limit, and exact stored logical Unicode. Verify the value in a nameplate and later `[pname]` dialogue; test blank and whitespace-only fallback. Include a maximum-length name and confirm no clipping. A correct static prompt alone is not an input pass.
3. Check the timed wait and slow ellipsis, line advancement, save/load, page labels, timestamps and the DLC Gallery in both editions. Verify language switching back to English and a representative existing locale restores their fonts and rendering. Compare player saves before/after using the project's isolated-save procedure, with no changes to real saves.
4. Negative controls: the original unshaped path must reproduce the known defect; removing the Latin fallback must expose or detect the missing `N`/`V`; altered placeholders or protected controls must be rejected by the existing validators. A font-cmap check or a mock substitutes for neither real shaping nor real input.

Capture and review actual frames only when separately authorized, using the workstation preview policy. Record exact game, engine, font, adapter, configuration and test artifact hashes; report dialogue, input, UI, edition binding and visual results separately. If any required surface fails or remains ambiguous, retain the blocked gate. Runtime/visual proof, not this plan, is required to clear the demonstrated failure.
